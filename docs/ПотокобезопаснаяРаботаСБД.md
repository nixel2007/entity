## Потокобезопасная работа с БД

### Проблема

Раньше менеджер сущностей работал одним коннектором на все потоки. У драйверов СУБД соединение не
потокобезопасно, и это ломалось двумя способами.

Транзакция была свойством коннектора, а не того, кто ее начал, поэтому фоновые задания завершали
транзакции друг друга:

```bsl
// Основной поток
МенеджерСущностей.НачатьТранзакцию();
МенеджерСущностей.Сохранить(Сущность);

// Фоновое задание в это же время
МенеджерСущностей.НачатьТранзакцию();
МенеджерСущностей.ЗафиксироватьТранзакцию(); // Фиксирует и запись основного потока
```

Операции вне транзакций шли по тому же общему коннектору, поэтому параллельные запросы рвали
протокол обмена с СУБД - вплоть до искаженного SQL на стороне сервера:

```text
Npgsql.NpgsqlOperationInProgressException: A command is already in progress: SELECT * FROM Авторы
Npgsql.PostgresException: 42601: syntax error at or near "INTO"
```

### Решение

Все обращения к БД идут через пул соединений. Соединение выдается контексту исполнения и не
разделяется с другими: контекст - это фоновое задание, а вне фоновых заданий - основной поток.

- **Операция** занимает соединение на время выполнения и сразу отдает обратно.
- **Транзакция** занимает соединение до фиксации или отмены. Операции контекста, пока транзакция
  открыта, получают то же самое соединение и попадают в нее - и через менеджер, и через любое
  хранилище сущностей.

Передавать что-либо между вызовами не нужно: контекст определяется автоматически.

```bsl
// Основной поток
МенеджерСущностей.НачатьТранзакцию();
МенеджерСущностей.Сохранить(Сущность);

// Фоновое задание работает своим соединением и своей транзакцией
МенеджерСущностей.НачатьТранзакцию();
МенеджерСущностей.ЗафиксироватьТранзакцию(); // Записи основного потока не касается

МенеджерСущностей.ОтменитьТранзакцию(); // Отменяет только свою запись
```

### Размер пула

Размер пула задается четвертым параметром конструктора и по умолчанию равен 10:

```bsl
МенеджерСущностей = Новый МенеджерСущностей(
    Тип("КоннекторPostgreSQL"),
    "Host=localhost;Port=5432;Database=test",
    Неопределено,
    10
);
```

Размер - это предел одновременно живущих соединений, то есть предел параллельной работы с БД.
Когда все соединения заняты, следующий контекст встает в очередь и ждет; освобожденное соединение
достается тому, кто ждет дольше всех.

Нулевой размер снимает предел и отключает постоянно живущие соединения: каждое обращение к БД
открывает свое соединение и закрывает его по завершении. Параллельность при этом не ограничена, но
за каждое обращение платится установкой соединения.

```bsl
МенеджерСущностей = Новый МенеджерСущностей(Тип("КоннекторSQLite"), СтрокаСоединения, Неопределено, 0);
```

Хранилища сущностей одного менеджера работают его пулом, поэтому предел общий на менеджер.
Хранилище, созданное в обход менеджера, заводит собственный пул.

### Незавершенные транзакции

Если фоновое задание завершилось, не зафиксировав и не отменив транзакцию, его соединение остается
закрепленным за уже несуществующим контекстом. Такие соединения пул отбирает у завершившихся
контекстов, когда свободных не осталось: незавершенная транзакция откатывается, а соединение
уходит следующему. Без этого исчерпанный пул ждал бы освобождения вечно.

Это страховка, а не штатный режим. Транзакцию следует завершать явно:

```bsl
МенеджерСущностей.НачатьТранзакцию();
Попытка
    МенеджерСущностей.Сохранить(Сущность);
    МенеджерСущностей.ЗафиксироватьТранзакцию();
Исключение
    МенеджерСущностей.ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

### Прямой доступ к БД

`ПолучитьКоннектор()` возвращает коннектор, открытый менеджером или хранилищем. Операции
библиотеки по нему не идут - он оставлен для запросов в обход библиотеки. Этот коннектор общий,
поэтому из нескольких потоков одновременно им пользоваться нельзя.

### Закрытие

`МенеджерСущностей.Закрыть()` закрывает все соединения пула, в том числе занятые контекстами.
